# Syscall and User-Mode Implementation Plan

Status: draft. Companion to `SYSCALL_DESIGN.md` (mechanism choice) and `USERSPACE_LAYOUT.md` (address space).

## Starting point

- **Design is settled.** `SYSCALL_DESIGN.md` picks SYSCALL/SYSRET. `USERSPACE_LAYOUT.md` describes a per-process address space. Neither is implemented.
- **GDT has no TSS and the user selectors are wrong.** `gdt.h` defines `GDT_USER_CS 0x2B` and `GDT_USER_DS 0x33`. Those are indexes 5 and 6, but `g_gdt[]` has only 5 entries, so user code at index 3 would be `0x1B`. This needs fixing first.
- **Memory is identity-mapped, with a single address space.** `TCB` has `address_space`, `user_entry_point` and `user_stack_base` fields, but nothing uses them.
- **Tasks are kernel functions.** `scheduler_add_task(name, fn, arg)` is the only way to start one.
- **Apps are compiled into the kernel.** `src/apps` and `apps.c` hold them, and the kernel is a PIE with no relocations.
- **FAT32 is working.** User programs could be loaded from disk.

## Phases

### 1. Ring-3 plumbing (no syscalls yet) - DONE

- Fix the GDT layout. SYSRET needs user data at STAR base+8 and user code at base+16, so the order is kernel CS, kernel DS, user DS, user CS.
- Add a 64-bit TSS with `rsp0` and load it with `ltr`. Update `rsp0` on every context switch.
- Add an `enter_user(entry, user_rsp)` routine using `iretq`.
- Test: run a tiny user stub that loops. Check that a privileged instruction such as `hlt` raises #GP, and that the kernel survives.

### 2. Per-process address space - DONE (first slice)

- Add user page tables with the U/S bit set, plus a shared kernel half. Keep a template PML4 for the kernel mappings.
- Move the kernel off the identity map and into the high half (`KERNEL_HIGH_HALF_BASE` already exists). This is the riskiest step, because the PIE kernel has no relocations and the page tables must be rebuilt.
- Alternative: keep the identity map for now and put user code in a separate low range with U/S set on its pages. This is weaker isolation, but much smaller. Recommended: start there and harden later.
- Add user-stack and heap setup with guard pages, reusing `stack_guard.c`.
- Handle page faults. A user fault should kill the process, not the kernel.

### 3. SYSCALL/SYSRET entry - DONE

- Set `EFER.SCE`, `STAR`, `LSTAR` and `SFMASK`.
- Write the entry stub. It does `swapgs` (or uses a per-CPU stack variable), switches to the kernel stack, saves registers, and dispatches through a table.
- Validate user pointers with `copy_from_user` and `copy_to_user`. Never trust a raw pointer.
- Start with a minimal set:
  - `exit`
  - `write` (to the console)
  - `yield`
  - `getpid`
  - `sleep`
  - `read_key`

### 4. Process loader - DONE

- Define a flat binary or minimal ELF64 static format for user programs. A flat binary is simpler to start with.
- Add a `process_create(path)` call that reads the file through `fs`, maps it, builds the stack, and creates a TCB with `address_space` set.
- Scheduler: when switching to a user task, load CR3 and set `rsp0`. Reap processes on exit.
- Add a small user-space library: syscall wrappers and `_start`.
- Build step: add a Makefile target that links user programs at their user base address and puts them on the FAT image.

### 5. File and window syscalls - DONE

- Add `open`, `read`, `write`, `close` and `readdir`, backed by FAT32.
- Add window syscalls so apps can draw into a window buffer. This is where a compositor would help.
- Port one existing app, such as Notes, to run as a real user process. It proves the whole path.

### 6. Hardening and tests - DONE

- Add tests for bad pointers, a stack overflow in user mode, unknown syscall numbers, and a user process that never yields (preemption).
- Update the docs and the README roadmap.

**Phase 1 status.** GDT reordered (user DS 0x1B, user CS 0x23, TSS 0x28), TSS loaded with `gdt_set_kernel_stack()`, `paging_map_user()` added, `user_enter()` in `usermode.c`, and the exception dump now shows RIP/CS/RSP. Verify with `make CC=clang USER_SELFTEST=1 uefi-loader` and boot: the user program runs `hlt` at CPL 3 and the kernel reports `Vector: 13`, `CS: 0x23 (ring 3)`. Known issue found on the way (not from this change): the `TESTS=1` build page-faults in the context-switch suite, so the GDT suite does not run there.

**Phase 3 status.** `syscall.c` / `syscall_entry.S`: EFER.SCE, STAR (SYSRET base 0x10), LSTAR, SFMASK (clears IF/DF/TF). Single-CPU entry stub uses globals instead of `swapgs` (`g_kernel_rsp0` mirrors TSS.rsp0, kept in sync by `gdt_set_kernel_stack`). Syscalls: `exit`, `write` (fd 1/2 to console), `yield` (no-op until phase 4), `getpid` (placeholder), unknown -> -ENOSYS. User pointers are validated by `paging_user_range_ok()` (page-table walk, U/S at every level) and user VAs are capped at `USER_VA_LIMIT` so SYSRET never sees a non-canonical RCX. Verify: `make CC=clang USER_SELFTEST=1 uefi-loader` and boot; expect `PASS ... (exit 42)`. `USER_SELFTEST=2` runs the old `hlt` -> #GP test. Limits: syscalls run with interrupts off; no `swapgs`/SMP; a fault inside a syscall kills the process (see the phase 6 fault-recovery note); arg 6 (R9) is not forwarded.

**Phase 4 status (first slice).** `src/user/` holds a tiny runtime (`user.h` wrappers, `crt0.c`, `user.ld`) and `hello.c`; `make user-apps` builds flat binaries and copies them to `out/uefi/APPS/`. `process.c`: `process_create(path)` finds the file on any volume, reads it into freshly allocated pages (zeroed, plus 4 extra pages for .bss/heap), maps image and a 16 KiB stack for ring 3 and allocates a kernel stack; `process_run()` runs it to completion (`user_run`/`user_return` save and restore the kernel context, so `exit` returns to the caller); `process_destroy()` unmaps and frees everything. Verify with `make CC=clang USER_SELFTEST=3 uefi-loader`: HELLO.BIN runs twice and the kernel carries on to the desktop. Also fixed: the syscall stub now preserves RDI/RSI/RDX/R8-R10 as the syscall ABI requires. (Superseded by phase 2: processes now have separate address spaces.)

**Phase 4 status (scheduler integration).** `process_spawn(path)` runs a program as its own scheduler task and `process_wait(handle, &code)` collects the exit code. ''Ring-3 code is preempted by the normal timer tick: the tick saves the interrupt frame (including SS/RSP) on the process's kernel stack and later resumes it with `iretq`, so no new switching code was needed. ''`yield` now waits for the next tick (`sti; hlt; cli`) when the scheduler is running. `getpid` returns the id of the task running the program. ''A CPU exception that arrives from ring 3 kills only that process (exit code `0x100 + vector`, e.g. 270 for a page fault) via `process_handle_user_fault()`. ''The scheduler now reuses slots of finished tasks and `scheduler_add_task` is safe to call while running (interrupts masked). ''Several spawned programs queue up and run one at a time (the user address space is claimed atomically). ''Verify with `make CC=clang USER_SELFTEST=4 uefi-loader`: a supervisor task spawns `count` (a busy loop preempted ~60 times), `hello`, `crash` and a missing file together, then launches `hello` twelve times; expect `[SUP] PASS`. ''**Launch UI.** Start menu > Programs opens a window with HELLO/COUNT/CRASH buttons; pressing Enter or double-clicking a `.BIN` in Files launches it too. `sys_write` also copies output into a 4 KB ring (`process_output_write/read`), and the desktop loop calls `app_programs_poll()` to show it and report the exit status (`process_poll` is the non-blocking `process_wait`). One program per Programs window (each window has its own console, see commit 29f1726; up to 4 windows). `read(0, ...)` (syscall 4) blocks for keyboard input: the Programs window does line editing and feeds `process_input_*`; Ctrl+D or closing the window ends the input. `sleep(ms)` (syscall 5) waits on the timer with interrupts opened between checks, so other tasks run (it parks the task until the deadline) and returns the time actually slept. Demos: `ECHO.BIN`, `TICK.BIN`. Also: syscalls still run with interrupts off except `yield` and the waits; `sleep`, blocking `read(0)` and blocking `win_event` park the task (`scheduler_block_current`, woken by the timer or `scheduler_wake_all(TASK_WAIT_INPUT)`) instead of spinning.

**Desktop as a task.** The desktop used to take over IRQ0 and run on a private stack outside the scheduler once all tasks had finished, so nothing could run beside it. It is now an ordinary scheduler task (`desktop_start()` adds it from the idle callback; the scheduler's tick stays on vector 32 and still drives `timer_tick`). The task switches to a private 64 KB stack because task stacks are 4 KB. The idle callback is one-shot and may add tasks: the finished task waits for the next tick instead of halting. Because tasks now share the CPU with the desktop, shared kernel state is protected: `pmm_*` and `kmalloc`/`kfree` run with interrupts masked (`irqlock.h`), and every public `fat_*` call runs with `scheduler_preempt_disable()` held (the tick still runs but does not switch tasks). Known gaps: see the locking note below. Verify with `make CC=clang USER_SELFTEST=5 uefi-loader`: the desktop gets ~68 turns while `count` runs in ring 3, survives `crash`, and ten more launches; expect `[DESK] PASS`.

**Phase 2 status (first slice).** Each process now has its own address space. `paging_create_address_space()` allocates a PML4 from the physical allocator and copies the kernel's PML4 into it, so every process shares the kernel mappings (identity map, higher half, MMIO) through the same lower-level tables; the process's image and stack go into private tables (`paging_map_user_in`), always at the same virtual addresses. The TCB gained `cr3` and `kernel_rsp0`; `scheduler_activate_task` loads them (`paging_activate`, `gdt_set_kernel_stack`) whenever a task is switched in, so a preempted process resumes with its own page tables and its own kernel stack. `paging_user_range_ok` walks the active CR3. The per-process lookups that used globals (`g_current`, the single-process claim) now hang off the task (`TCB.address_space` -> `process_t`), `getpid` asks the running process, and `PROCESS_ERR_BUSY` is gone: any number of programs can be loaded at once, limited only by the 8 scheduler task slots and memory. `process_destroy` leaves the address space, then frees its tables and pages. The kernel itself did not move to the high half; it stays identity mapped and shared, which is what kept this change small. Verify with `make CC=clang USER_SELFTEST=6 uefi-loader`: four `ISO.BIN` processes run at once (all at the same virtual addresses) and each checks that its `.data`, `.bss` and stack contents survive the others' activity, then a crash next to a live process and twelve more launches; expect `[ISO] PASS`. Known gaps: a PML4 slot the kernel gains after a process was created is not copied into it (only matters for memory above 512 GB); kernel memory is not unmapped from user address spaces, it is just supervisor-only.  Output and keyboard input are per program (each spawn has its own console); a Programs window shows one program at a time, and "Start menu > Programs" or opening a .BIN while all windows are busy opens another window.

**Phase 5 status (file syscalls).** `sysfile.c`: `open(path, flags)` (6), `close(fd)` (7), `readdir(fd, out)` (8), and `read`/`write` accept fds >= 3 (fds 0-2 stay the console). Each process has a table of 8 descriptors (`process_t.files`, allocated on first open). Paths are `/DIR/NAME` with no drive letters; the default volume is searched first, then the others. Flags: `O_RDONLY` (a file or a directory) and `O_WRONLY` (create or truncate). Because the FAT driver only reads and replaces whole files, files are buffered whole: `open` loads a file into kernel memory (max 256 KiB, else `-EFBIG`) and `read` serves it from there; a write-opened file collects `write` calls in memory and `close` stores it (the file is only created or truncated then, and `close` returns `-EIO` if that fails). Writes always go to the default volume. `readdir` returns one `sysfile_dirent_t` (size, attr, 128-byte name) per call, 0 at the end. Files left open at exit are closed by `process_destroy`; pending writes are stored unless the process was killed by a fault. File operations open interrupts (`sti`) for their duration, since the disk drivers need the timer, and the FAT driver serialises itself. Errors: `-ENOENT`, `-EBADF`, `-EISDIR`, `-ENOTDIR`, `-EMFILE`, `-EFBIG`, `-EFAULT` (user pointers, including the path, are validated page by page), `-EINVAL`, `-EIO`. Verify with `make CC=clang USER_SELFTEST=7 uefi-loader` on a machine that also has a data disk (e.g. `scripts/make-disk-image.py`, attached as a second AHCI drive): `FILES.BIN` runs 31 checks, a second run proves a file left open was stored at exit, and concurrent runs prove separate descriptor tables; expect `[FILE] PASS`. Seek, append, in-place writes, stat, mkdir and unlink were added afterwards (see part 2), and files over 256 KiB are streamed (see the big files note). QEMU's `fat:rw:` virtual disk gets file contents wrong when a file is rewritten with a longer one; that is a QEMU limitation, not the driver, so test writes on a raw image.

**Phase 5 status (file syscalls, part 2).** `lseek(fd, off, whence)` (17) works on read and write files (SET/CUR/END; the position is capped at 256 KiB, a seek past the end of a write file leaves a zero-filled hole). `open` takes two more modes: `O_RDWR` (2) keeps the contents, creates the file if missing, reads and writes at the position; `O_APPEND` (4, with `O_WRONLY` or `O_RDWR`) keeps the contents and every write goes to the end. A kept file is only stored on `close` if something was written. `stat(path, dirent_t *)` (18) searches all volumes like `open`; `unlink(path)` (19) deletes a file or an empty directory (`-ENOTEMPTY`, `-EACCES` for read-only, `-EINVAL` for `/`); `mkdir(path)` (20) makes a directory (`-EEXIST`). Both write calls use the default volume. `FILES.BIN` now runs 64 checks (`USER_SELFTEST=7`, expect `[FILE] PASS`). Not yet: rename, truncate, files over 256 KiB (the heap is 4 MB and files are held whole), a file open elsewhere is not protected from `unlink`. Note: the Makefile does not track `USER_SELFTEST`, so run `make clean` when switching between self-test numbers.

**Phase 5 status (default apps).** The desktop icons, the Start menu and the boot-time windows now open the user programs: `app_launch_notes()` and `app_launch_files()` (in `app_programs.c`) start `/APPS/NOTES.BIN` and `/APPS/EXPLORER.BIN` with `process_spawn_detached` (a spawn nobody waits for: its slot is released when the program ends). They fall back to the built-in kernel Notes and Files when the file is missing, no window slot is free (`syswin_free_slots()`), or no task slot is free, so the desktop never ends up with no way to open a file. Files is single instance: `process_spawn_active()` finds a running Explorer by its path and `syswin_raise_pid()` restores and raises its windows instead of starting another. Notes opens a new window each time, like the built-in one. The self-test builds (`KERNEL_USER_SELFTEST`) keep the built-in apps at boot, because the tests count user windows; `USER_SELFTEST=8` checks the launcher separately (the Notes launcher opens a user window, takes one slot and frees it again). Checked by hand with a screenshot of a normal boot (a user-mode Notes and Files side by side) and a real mouse drag of the Files corner, which grew the window and re-laid out the list. (This was first built with the kernel Notes / Files kept as a fallback; they are gone now, see the next note.)

**Phase 5 status (Paint, About, and the kernel apps removed).** `PAINT.BIN` and `ABOUT.BIN` are user programs. Paint keeps no canvas of its own: the picture lives in the window's surface and Paint draws into it with `win_fill` (a 3x3 dab per step along the drag). About shows the display size and the uptime and refreshes every second with `win_wait(..., 1000)`; for that it needs two new syscalls, `uptime_ms()` (29) and `screen_size()` (30). `SYSWIN_MAX` went from 4 to 8, since Notes, Files, Paint and About can all be open at once. The kernel's own Notes (`apps.c`) and Files (`explorer.c`, deleted) are gone: `app_launch_notes()` / `app_launch_files()` start the programs and, when they cannot be started (file missing, no window or task slot), show a message window (`app_message_open`) that says which. Paint and About had built-in fallbacks at first; they were removed too, so the message window is the only fallback. Because the desktop now depends on `\APPS`, **every install path ships it**: the in-OS Setup copies the medium's `\APPS` to the new ESP (`copy_apps`, 19 files verified byte for byte), `install.sh` copies `<source>/APPS` to `<ESP>/APPS`, and the installer package, `make vm-disk` and `make vbox-disk` include an `APPS` folder. Checked by running Setup in QEMU onto a blank 600 MB disk, reading it back with `scripts/fat32-ls.py` (all programs present, `--check` clean) and booting that disk alone: Notes and Files opened from the installed `\APPS`. Not checked: `install.sh`, `make vm-disk` and `make vbox-disk` (they need Linux, mtools and VirtualBox; only `bash -n` and the Makefile edits were reviewed). The self-test builds open no windows at boot. `USER_SELFTEST=8` runs Paint (palette, drag, Clear, using `syswin_test_pixel`) and About (title drawn).

**Phase 5 status (double buffering).** The desktop now draws into an off-screen copy of the screen and copies only the finished dirty rectangle to the real framebuffer (`fb_set_buffered` / `fb_present`, see `docs/WINDOW_MANAGER.md`), so programs that redraw often (a Paint drag, a resize) no longer show half-drawn frames. Program surfaces are blitted into the same off-screen copy by `uw_paint`. The pointer is drawn straight on the screen on top of the picture, so erasing it is presenting a 12x19 patch of the clean copy. Live resize (above) relies on this: without it a repaint on every 60 ms step would flicker. Checked with screenshots of a normal boot and of a drag with the button held (the window and its contents follow, the pointer is intact), and by the self-tests 5, 7, 8 and 9, which run the desktop loop through the new path. Flicker itself cannot be seen in a screenshot, so that part is only checked by reasoning (the screen is written once per rectangle, from finished pixels). Cost: 4 MB of memory at 1280x800 and one extra copy per repaint.

**Phase 5 status (big files).** Files over 256 KiB (`SYSFILE_BUF_MAX`) are no longer refused: they are streamed instead of held in memory, up to 2 GiB - 1 (`SYSFILE_MAX_SIZE`). The FAT driver gained `fat_file_t` (`fat_file_open / create / read / write`): reads and writes at byte offsets, a cursor into the cluster chain so sequential access does not walk the chain from the start each time, whole-sector transfers for the aligned middle, a read-modify-write only for partial sectors, and every write extends the file as needed and updates the directory record, so the file is consistent after each call (a killed program leaks nothing). In `sysfile.c` a file is *buffered* when it is at most 256 KiB and *streamed* above that. `open` of a big file for reading, `O_RDWR` or `O_APPEND` streams at once. A write handle that starts buffered switches by itself when its data passes 256 KiB (`spill`): the file is created or emptied on disk at that moment (a loaded file is overwritten in place), the buffer is written out, a seek hole is filled with zeros, and from then on writes go straight to disk. `read` and `write` on a streamed file move at most 64 KiB (`SYSFILE_CHUNK`) per call, so a program must loop on short counts (the user programs already did); the disk data goes through a kernel bounce buffer because the disk drivers cannot DMA into user addresses. `lseek` in a streamed file stays within `[0, size]` (`-EINVAL` past the end; FAT has no holes). New error `-ENOSPC` (volume full). `FILES.BIN` writes a 1 MiB + 1234 byte file, reads it back in odd pieces, seeks, overwrites 16 bytes in place, appends, and grows a small file past the limit while it is open (30 more checks, run once, `USER_SELFTEST=7`). Limits: no preallocation, no sparse files, a write that fails half way can leave the file shorter than asked (the size is always what was written), and the kernel's own explorer and Notes still read whole files.

**Phase 5 status (window syscalls).** `syswin.c`: `win_create(title, w, h)` (9) makes a window whose client area is w x h (16..800 x 16..600) and returns an id; `win_close` (10); `win_blit` (11), `win_fill` (12) and `win_text` (13, 8x8 font, scale 1-8) draw into a pixel surface (0x00RRGGBB) that the kernel keeps for the window (pmm pages, identity mapped), taking a `syswin_op_t` by pointer; `win_event(id, ev, block)` (14) returns key, mouse down/move/up and close events (16-byte `syswin_event_t`, queue of 32), blocking if asked. Drawing is clipped to the surface. Limits: 4 windows on the system, 2 per program. **The window manager is only touched by the desktop task**: syscalls hand work over through a per-window state (`PENDING` -> `ACTIVE` -> `DEAD`/`CLOSING`) and a dirty flag, and `syswin_poll()` (called from the desktop loop next to `app_programs_poll`) creates the windows, repaints dirty ones and closes released ones; in the other direction the window callbacks push events and wake the program. `win_create` waits up to 3 s for the desktop to create the window (`-ENODEV` if there is no desktop). When the user closes a window with the X button the program gets `EV_CLOSE`; the window is then dead (`-EBADF` for drawing and reading) until it calls `win_close`. Windows a program leaves open are closed when it exits. `fb_blit()` was added to the framebuffer layer. Demo: `WINDEMO.BIN` (scribble with the mouse, type text); launch it from Files (Enter or double-click). Verify with `make CC=clang USER_SELFTEST=8 uefi-loader`: `WINTEST.BIN` runs 24 checks and leaves windows open, four more runs prove nothing leaks, and `WINEV.BIN` blocks until the supervisor injects key, mouse and close events; expect `[WIN] PASS`. The self-test does not check what appears on screen. Not yet: a user-space library (fonts, widgets). (Arrow keys, `win_wait`, `win_move`, `win_resize` and user resizing were added afterwards, see parts 2 and 3.)

**Phase 5 status (window syscalls, part 2).** Arrow keys and Delete already reached programs as `EV_KEY` with `ch` = 0x1C Left, 0x1D Right, 0x1E Up, 0x1F Down, 0x7F Delete (the PS/2 codes); `user.h` now names them `KEY_*`. `win_wait(id, ev, timeout_ms)` (21) is `win_event` with a deadline: 1 = event stored, 0 = timed out (0 ms polls), negative = window gone. The scheduler treats a `TASK_WAIT_INPUT` block with a non-zero `wake_ms` as timed, so an event wakes it at once and the tick wakes it at the deadline. `win_move(id, x, y)` (22) puts the window's top-left at (x, y); it is clamped so the title bar stays on screen, and un-maximizes. `win_resize(id, w, h)` (23) gives the window a new client size (same 16..800 x 16..600 limits); the kernel allocates a cleared surface, the desktop task swaps it in under `irq_save` (so a drawing syscall never sees a half-swapped surface) and resizes the frame, and `win_resize` returns once that is done (`-EBUSY` if a previous resize is still pending, `-ENODEV` if the desktop did not answer in 3 s). The contents are lost, so the program redraws. `WINTEST.BIN` has 17 more checks and `WINEV.BIN` receives an arrow key through `win_wait` (`USER_SELFTEST=8`, expect `[WIN] PASS`). Still not there: a user dragging the window edge does not resize the surface (the surface is clipped or padded), no maximize/minimize requests from the program, no Home/End/PageUp/PageDown (the mouse wheel arrives as `EV_WHEEL`: x, y = pointer, `(int)ch` = notches, positive = scrolled up).

**Phase 5 status (window syscalls, part 3: user resizing).** `win_resizable(id, 1)` (28) opts a window in to being resized by the user. The window manager now has a `resized` callback, called when the mouse is released after dragging the corner grip and after maximize / restore. For an opted-in window the desktop task allocates a cleared surface of the new client size (clamped to 16..800 x 16..600; a frame dragged beyond the limit shrinks back), swaps it in under `irq_save`, frees the old one and queues `EV_RESIZE` (7) with the new size in `x`/`y`; the program redraws. If memory is short the old surface stays. A maximized window keeps its frame and the surface stops at 800 x 600. Windows that do not opt in behave as before (the frame resizes, the surface is clipped). While the drag is in progress the window manager calls `resized` at most every 60 ms (`LIVE_RESIZE_MS`), so the surface and the program's layout follow the drag; the last call comes when the button is released. `NOTES.BIN` and `EXPLORER.BIN` opt in and lay themselves out from the current size. `USER_SELFTEST=8` runs `RESZT.BIN`, using a test hook that makes the desktop task resize the window as a drag would (a 300x200 request, then a 900x700 one clamped to 800x600). The mouse path itself (`wm_mouse_up`) is only checked by hand. Not there: per-window minimum sizes chosen by the program, programs asking for maximize / minimize.

**Phase 5 status (mouse modifiers and the user library).** Mouse events now say which of Shift / Ctrl / Alt were down: the PS/2 driver stamps `mods` on mouse events as it already did for keys, the desktop passes them on with `wm_set_key_mods()` before it handles the event, and `uw_mouse` puts them in `ch` of `EV_MOUSE_DOWN / MOVE / UP / DOUBLE` (for `EV_KEY` they stay in `x`). `src/user/ulib.h` is a header-only helper library (`ulib_*`, all `static inline`, so nothing extra is linked): string copy / concatenation / case-insensitive compare / extension test / number to text / size text / basename, `ulib_mods(ev)` (the modifiers of a key or mouse event), `ulib_in_rect`, `ulib_outline`, `ulib_text_fit` (cut to a width) and `ulib_button` with a style struct. Notes and Explorer use it instead of their own copies. Notes: Shift+click extends the selection. Explorer: Ctrl+click adds or removes an item, Shift+click and Shift+Up/Down/PageUp/PageDown/Home/End select a range, Ctrl+A selects all, and Delete removes every marked item (or the current one when none is marked); the status bar shows "N of M selected". `USER_SELFTEST=8` checks Shift+click in Notes and range / Ctrl+click multi-delete in Explorer; whether the real mouse reports modifiers is only checked by hand. Not there: Alt-based shortcuts, a Ctrl+click toggle in Notes, drag-and-drop, copy / move in Explorer.

**Phase 5 status (Notes as a user process).** `src/user/notes.c` is the Notes editor rewritten as `NOTES.BIN`: it opens a 480x300 window with `win_create`, draws text and the status bar with `win_fill`/`win_text`, edits a 4096-byte buffer from `EV_KEY` events (Backspace, Enter, Ctrl+S) and loads and saves with `open`/`read`/`write`/`close` (saved files use CR LF line ends like the built-in Notes). It scrolls to keep the cursor visible, names new files `/NOTEn.TXT` on the default volume, and sets its title with the new `win_title(id, title)` syscall (16). Two small additions made it possible: `process_spawn_arg(path, arg)` starts a program with an argument string and the `getarg(buf, len)` syscall (15) reads it; `NOTES.BIN /DIR/FILE.TXT` opens that file and saves back to it. Start it from the Programs window (new NOTES button) or Files. Verify with `make CC=clang USER_SELFTEST=8 uefi-loader`: the supervisor starts `NOTES.BIN /NTEST.TXT`, injects keys, Ctrl+S and a close, then reads the file from the disk; a second run must load it and append. Also checked by eye in a screenshot. The built-in kernel Notes stays (it is what Files and the desktop icon open for `.TXT`). **Cursor movement (added later):** Left/Right/Up/Down move the cursor (Up/Down keep the column), Ctrl+A / Ctrl+E jump to the start / end of the row, a mouse click places it, Delete and Backspace remove text, and typing inserts at the cursor. The view scrolls to keep the cursor row visible. `USER_SELFTEST=8` runs a third Notes session that edits the saved file with Up, Left, a typed character, Delete, Down and another character. Because `NOTES.BIN` now carries a row table, `PROCESS_EXTRA_PAGES` went from 4 to 12 (48 KiB of zeroed .bss/heap per process). Limits: no selection, no Home/End/PageUp/PageDown keys (use Ctrl+A / Ctrl+E), the program cannot save back to a file on a non-default volume (writes go to the default volume), and a file left open is not locked.

**Phase 6 status (hardening tests).** `USER_SELFTEST=9` runs three new programs under a supervisor task. `PROBE.BIN` makes about 34 bad calls and expects each to fail cleanly: null, kernel-only, kernel-half, unmapped and wrapping pointers and absurd lengths for `write`/`read`/`open`/`getarg`/`win_create`, bad descriptors and window ids, unknown flags and sizes, and unknown syscall numbers (including 2^32, which must not alias `exit`, and negative numbers) which return `-ENOSYS`. It exits 0 only if every one failed as expected, otherwise with the number of the first that did not. `STACKOVF.BIN` recurses until it runs off the 16 KiB stack into the unmapped guard page; the kernel must kill it with a page fault (exit 270) and free everything, which is checked by running it eight times and by `process_live_count() == 0`. `SPIN.BIN` loops about 400 million times without any syscall; while it runs, a second program must start, finish and be reaped, and `SPIN` must still be running at that point (it is preempted by the timer, it never blocks the others). A mixed batch (probe, stack overflow, crash, hello) checks that each program gets its own outcome. Verify with `make CC=clang USER_SELFTEST=9 uefi-loader`; expect `[HARD] PASS`. Not covered: a program that is killed while blocked in a syscall, and fuzzing of syscall arguments beyond the hand-written cases.

**Phase 6 status (faults inside syscalls).** A ring-0 exception while the kernel serves a syscall no longer halts the machine. `syscall_dispatch` brackets every call with `process_syscall_enter/leave`, which set `process_t.in_syscall` and record the scheduler's preempt-lock depth. `exception_dispatch` now calls `process_handle_kernel_fault()` for ring-0 faults: if a running process is inside a syscall it is killed with `PROCESS_EXIT_FAULT_BASE + vector`, the preempt-lock depth is restored (the FAT driver holds it during calls), and control unwinds to `process_run`'s caller exactly as for a ring-3 fault. NMI, double fault and machine check, and ring-0 faults outside a syscall, still halt. The test uses a self-test-only syscall (`SYS_TEST_KFAULT`, `KFAULT.BIN`) that dereferences null, with and without the preempt lock held; `USER_SELFTEST=9` checks the kill, the lock release and that a program running beside it is unaffected. Limits: other kernel state the aborted syscall touched is not rolled back (a half-updated FAT operation, a window left PENDING, a `kmalloc` block it owned leaks); locks other than the preempt depth do not exist yet. Tip for running the test under QEMU: the boot volume must be on an AHCI disk (`-device ich9-ahci,id=ahci -device ide-hd,drive=esp,bus=ahci.0`), the default virtio-blk disk is not seen by the FAT driver.

**Locking (gaps closed).** The public page-table editors in `paging.c` (`paging_map_range`, `_map_mmio`, `_unmap_identity_range`, `_map_user`, `_create_address_space`, `_map_user_in`, `_destroy_address_space`, `_unmap_user`, `_activate`) now run with interrupts masked through `irq_save`/`irq_restore`, which nest, so the kernel's shared lower-level tables, the table pool and the PML4 copy made for a new address space cannot be edited by two tasks at once. `console_write_string` and `console_printf` hold `scheduler_preempt_disable()` so one message is never split by another task's output. Opening a file (lookup then read, or parent lookup then name lookup), the flush-on-close, and `process_create` (find then read the image) hold the preempt lock across their several FAT calls, so a directory cannot change between the lookup and the read. Verified with `USER_SELFTEST=3` through `9` (all pass). Still not covered: the framebuffer and window manager are touched only by the desktop task by design; there is no lock around FAT *writes* from a task that is preempted by an interrupt handler (none exists yet); interrupt handlers that print can still interleave with a task's message.

## Risks

- **The high-half move (phase 2).** Anything that holds physical or identity pointers will break, including the framebuffer, MMIO, AHCI and NVMe buffers, and DMA. That is why it is deferred.
- **No relocations in the kernel.** Static pointer tables must not be used in the syscall table. Use a `switch` or a flat array of function indexes.
- **Interrupts in the syscall path.** Preemption (`scheduler_on_timer_tick`) must handle a task that is in the middle of a syscall.

## Suggested first slice

Phases 1 and 3 with the identity map left alone: a ring-3 stub that calls `write` and `exit`. That proves the hard hardware parts. Phases 2 and 4 then build on it.

**ELF loader.** User programs are now ELF64 executables instead of flat binaries. `src/user/user.ld` links each one at `0x7F0000001000` with two `PT_LOAD` segments, each starting on its own page: R+X (ELF header, code, constants) and R+W (`.data`, `.bss`). `process_create` (`process.c`) reads the header, checks it (`ET_EXEC`, x86-64, at most 4 segments, all inside the user range below the stack guard page, no two segments sharing a page, entry inside an executable segment, file ranges inside the file), reads each segment straight into its physical pages at its offset from the lowest page, and leaves the `.bss` zeroed. Code and constants are mapped read-only; data, `.bss`, the heap pages and the stack are writable. The entry point is `e_entry`. A bad ELF returns `PROCESS_ERR_BADELF`. A file without the ELF magic is still loaded as a flat binary (one writable segment at the load base), so old programs keep working. Programs keep the `.BIN` extension on disk, so no path changed. Not done: dynamic linking and relocations (files must be linked for their address), `PT_TLS`, no-execute pages (the page tables have no NX bit, so read-only is enforced but data is still executable), and `ET_DYN` (PIE) files. Verified with `USER_SELFTEST=6`, `8` and `9` plus booting the desktop (Notes and Explorer start as ELF). Note: delete `out/kernel/*.o` when switching `USER_SELFTEST`, or the objects mix.

**Notifications.** `notify(text)` (31) shows a toast above the taskbar (text cut at 33 characters). The syscall copies the text into a small queue (`desktop_notify_post`, safe from any task) and the desktop loop drains it, because only the desktop task may draw. `TOAST.BIN` (`run toast`) is the demo program.

**Windows programs.** `peinfo(out[4])` (32) fills in the heap base, heap size, program image base and Win32 DLL base of a PE program (`-ENOSYS` for any other program); the Win32 runtime uses it to find the heap block the loader mapped for it. The PE loader, the runtime and the tests are described in `docs/WIN32.md`. The scheduler now also saves and restores each task's x87/SSE state (`TCB.fx_state`) at every task switch.
